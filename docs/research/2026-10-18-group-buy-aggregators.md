# 团购第三方聚合核销服务商对比

- 对应 issue：#6「团购第三方聚合核销服务商对比」
- 调研日期：2026-10-18。官方文档、价格、授权书都是当天读取的。平台规则和服务商报价变动频繁，签约前必须重新核对。
- 背景：北京单店美发；Go 后端，闭源，以后可能做 SaaS；在美团/大众点评、抖音卖团购，可能加上小红书；已决定把核销接入外包给第三方聚合服务商，自己暂不做平台官方服务商。
- 范围：issue 列的五个问题，即服务商与官方资质、API 能力（核销、券状态、结算金额）、收费与门槛、小红书开放情况、合规风险。

## 0. 结论速览

1. **能同时覆盖美团（含点评）和抖音、并提供 API 给自有系统调用的聚合服务商，公开可查的有两家**：无限聚核（elys.cn，宁德无限递归网络科技有限公司）和云飞API（yunfeiapi.com，上海云飞网络科技工作室）。CSDN 上还有几家不署名的推广。**两家都不支持小红书**；云飞另外支持快手。[服务商自述]
2. **两家的门店授权都走平台官方授权**：美团是经营宝 App 扫码授权，抖音是在来客里做「服务应用授权」。没有看到要商家把账号密码交给服务商、模拟登录商家后台这类非官方做法。[服务商自述，授权机制本身为官方已核实]
3. **最大的合规风险是商业模式本身，不在技术上。** 美团《运营管理规则》禁止开发者「通过接口转让、接口数据传输、售卖等方式提供给其它软件厂商应用」，也禁止「将对接功能以任何形式嵌入到第三方系统，或二次封装提供给第三方进行合作对接」。聚合服务商把自己的美团接口能力封装后卖给其他开发者，**字面上和这条规则冲突**。美团一旦处罚，服务商名下所有门店会一起断。[官方已核实规则原文；冲突判断为推断]
4. **单店自己直连美团不可行**。美团服务零售自研品牌入驻标准规定，丽人·美发要求「单个二级类目的品牌经营宝在线门店数量≥30家」；走服务商身份要 Web 应用防火墙证明、等保证明或网络安全保险，还要 10 万元保证金。[官方已核实]
   **抖音的自研商家入驻指南里没有写门店数门槛**，单店有可能自己直连，但能力开通要人工审核，平台介绍也说开放能力主要面向「规模以上连锁商家」。[官方已核实；单店能否通过审核未知]
5. **结算金额**：聚合 API 能拿到售价、用户实付和补贴分摊，**拿不到平台最终结算给商家的金额（扣佣金后）**。云飞文档直接写明「不是平台最终结算给商家的入账金额」。官方的结算类接口在美团属于「高级模块」，需要审核；抖音要等核销 1 小时后才有预计分账单。[官方已核实 + 服务商自述]
6. **小红书**：公开的小红书开放平台（open.xiaohongshu.com）是电商接口，在文档站里搜「团购」结果为 0，**没有公开的团购核销 API**。[官方已核实（文档站检索结果）]
7. **建议**（第 7 节展开）：现阶段可以用聚合服务商**过渡**，首选无限聚核，原因是价格公开、全程 HTTPS、公开了美团合作授权书。代码里必须做一层平台适配，聚合服务只是其中一个可替换的实现。抖音另外试一下自研商家直连。小红书先在官方商家后台手工核销。将来做 SaaS 时，**不能把 SaaS 建在聚合服务上**，必须自己成为美团、抖音的官方服务商。

## 2. 能否用 API 核销、查券状态、拿结算金额

### 2.1 平台官方接口有什么（决定聚合服务商的能力上限）

**美团·到店综合（服务零售，businessId=58；美发属于这个大类）[官方已核实]** [MT1–MT5]

| 能力 | 官方接口 | 要点 |
|---|---|---|
| 验券前校验 | `POST https://api-open-cater.meituan.com/ddzh/tuangou/receipt/prepare`（输码验券校验） | 返回可验张数、`dealPrice` 售卖价、`dealMarketPrice` 市场价、`paymentDetail` 支付明细、`platformAmount`/`merchantAmount` 补贴分摊、券过期时间、`platform`（1=美团，2=点评）、`verificationType`（是否在可用时段）。**点评券和美团券走同一套接口** |
| 核销 | `.../ddzh/tuangou/receipt/consume` | 带 `requestId` 幂等键，一次最多 100 张。返回订单号、售价、支付明细、补贴分摊、团购次卡信息 |
| 撤销 | `.../ddzh/tuangou/receipt/reverseconsume` | **只能撤销当天核销、且核销后不超过 10 分钟的团购券**；不支持平台次卡和拼团 |
| 查券 | `.../ddzh/tuangou/receipt/getconsumed`（查询已验券信息）、`querylistbydate`（验券记录）、`querybymobile`（手机号查可用券） | — |
| 结算/佣金 | 到店综合（客户）的「查询账期收入明细」`/ddzhkh/finance/income/detail` | 返回 `commission` 费率、`commissionAmount` 佣金、`settleAmount` 结算金额。但原文说明：「财务业务接口属于高级模块，适用于部分行业，若您有开通诉求，您可提交工单，或联系您对应服务零售业务销售/业务运营审核确认后，才可接入对接」 |
| 券码位数 | — | 服务零售券码从 2025-07 起逐步由 10 位升到 13 位。**系统里的券码字段不要写死长度** |

**抖音·生活服务商家应用 [官方已核实]** [DY1–DY5]

| 能力 | 官方接口 | 要点 |
|---|---|---|
| 验券准备、验券 | `certificate.prepare`、`certificate.verify` | 抖音码必须先 prepare 拿到 `encrypted_code`，再 verify |
| 撤销 | `certificate.cancel` | 订单状态从已使用回退到待使用。时限为核销后 1 小时（官方能力页摘要和云飞文档都这么写） |
| 券状态 | `certificate.get`（单个）、`certificate.query`（批量） | `GET https://open.douyin.com/goodlife/v1/fulfilment/certificate/get/`，返回原价、实付、平台优惠等金额字段 |
| 分账/结算 | `ledger.query_record_by_cert`（按券查分账明细）、`settle/bill/composite_query`（综合行业账单详情） | 原文：「券码核销 1h 后生成分账单」，而且是**预计分账金额**，「实际的分账动作、提现动作并未发生」。官方建议对账以账单详情接口为准 |
| 接入身份 | 自研商家、技术服务商两条路 | 能力开通要申请「门店管理、团购核销对账、团购核销」，提交使用场景后审核 |

### 2.2 聚合服务商暴露了哪些接口

| 能力 | 无限聚核 [E3] | 云飞API [Y2][Y3] |
|---|---|---|
| 授权 | `POST /api/hexiao/v2/get/auth/url` 获取美团/抖音授权链接，`platform=1` 为美团，`2` 为抖音；可配 Webhook 接收授权事件；另有美团取消授权链接接口 | 美团：生成授权码，用经营宝管理员账号扫码；抖音：先在来客里授权，再绑定；快手另有步骤 |
| 预核销/查券 | `ddzh-tuangou-receipt-prepare`，返回 `ticketInfo`，后面核销要原样回传 | 「查券和验券」同一个接口，用 `type` 区分；**查券不收费** |
| 核销 | `...-receipt-consume`，返回 `consumeCredential` | 同上；**验券成功才扣费** |
| 撤销 | `...-receipt-cancel` | `/reverse/consume` 和批量撤销；美团只支持到店综合券，餐饮券「开发中」 |
| 券状态 | 美团原生：查询已验券信息；抖音原生：券状态查询、批量查询 | 已授权门店查询、手机号查可用券 |
| 核销记录 | `...-receipt-querylistbydate` | 文档目录里没有看到 |
| 结算金额 | **没有对账接口**（文档未提及） | 有「订单券码分摊金额查询」；但原文写明：「验券接口返回的金额只能作为订单流水金额，不是平台最终结算给商家的入账金额，具体结算金额请以平台（美团经营宝、来客核销、快手商家平台）结算为准」 |
| 传输安全 | API Host 是 `https://newopen.elys.cn`，用 Bearer key | 文档里的接口地址是 **`http://`**（`http://wspacebot.yunfeiwork.com/...?access_token=...`），token 放在 query 里，明文 HTTP。**需要问能不能用 HTTPS** |
| SDK | 有 AI 接入提示词（`sdk.md`），没看到 Go SDK | 只有 Java SDK（gitee 开源，公测版） |

**小结 [推断]**：核销、撤销、查券状态两家都能做到，基本是官方接口的透传。**结算金额（扣佣金后的到账金额）两家都给不了**；美团的财务接口需要单独审核，抖音的分账接口两家都没有暴露。对账还得靠美团经营宝、抖音来客后台导出。

## 5. 合规风险

### 5.1 接入方式是否「非官方」

- **两家都用平台官方授权流程**，没有发现抓取、模拟登录商家后台：
  - 美团扫码授权是官方能力：「引导商家使用经营宝App扫一扫功能完成授权……免去商家登录的环节」，服务零售 businessId=58 需选门店授权，59 需选客户授权 [MT9]。云飞文档要求「用美团经营宝app的管理员账号扫码」[Y5]。
  - 抖音要求商家在「抖音来客 → 店铺管理 → 服务应用授权」里授权 [DY6][Y6]。
  - 美团官方授权页也有「账号密码」登录样式（qrMode=1），但那是在 `open-erp.meituan.com` 的官方页面上输入的 [MT9]。**判断标准**：如果有服务商要求商家把美团或抖音账号密码填到服务商自己的页面，或者要求开着电脑或手机保持商家后台登录，就是非官方接入，应该直接排除。

### 5.2 商业模式与平台规则的冲突（主要风险）

美团《运营管理规则》（2026-08-07 更新）原文 [MT10]：

> 开发者不得复制、模仿、修改、篡改、翻译、改编、出借、出售、转许可、在信息网络上传播或转让技术合作中心服务和/或相关软件，也不得将开发完成后的接口包含但不限于技术方式，通过接口转让、接口数据传输、售卖等方式提供给其它软件厂商应用……
>
> 开发者与技术合作中心对接产品仅能应用于自身。开发者申请上线后，开发者不得将对接功能以任何形式嵌入到第三方系统，或二次封装提供给第三方进行合作对接。

- **[推断]** 聚合核销服务商的产品形态，就是把自己在美团的接口能力封装后卖给其他开发者，让对方嵌入自己的系统。这和上面两句话字面冲突。无限聚核的授权书写的是「使用API为其商户提供相关产品服务」，没有写允许转给其他软件厂商。
- **后果 [推断]**：美团可以「调整、暂停或提前终止与开发者的合作」。服务商一旦被处罚，我们的核销会立即中断，而且没有任何合同能约束美团。
- **对我们自己的影响 [推断]**：规则约束的是服务商（开发者），不是商家。单店商家用第三方系统核销自己的券，本身不违反平台对商家的规则，最坏结果是核销中断。**但如果以后我们做 SaaS，再通过聚合服务给其他美发店核销，我们就是规则里说的「其它软件厂商」，风险会直接落到我们的产品上。**
- 抖音的《生活服务技术服务商管理规范》（1.0 于 2025-05-22 发布；2.0 于 2026-10-14 上线）全文在外部知识库，本次**没有读到**有没有类似的转售条款 [DY9]。[未找到]

### 5.3 其他风险

- **数据与隐私**：核销接口会返回用户手机号（美团返回脱敏号码，如 `185****1212`）、订单号等。经过聚合服务商时，数据会多一个处理方。应该签数据处理协议，确认服务商不留存、不另作他用。[推断]
- **传输安全**：云飞文档里的接口是明文 HTTP，access_token 放在 URL 里 [Y3]。[服务商自述的文档内容]
- **主体稳定性**：两家都是小主体，一家是 2026 年 ICP 备案的公司，一家是「工作室」。预充值余额有跑路风险，所以只做小额充值。[推断]
- **撤销时限**：美团 10 分钟、抖音 1 小时，这是平台规则，聚合服务改变不了。前台流程要先确认再核销。[官方已核实]

## 7. 建议

**单店阶段（现在）**

1. **美团/点评：用聚合服务商过渡，首选无限聚核。** 理由：价格公开且很低；全程 HTTPS；公开了美团授权书，可以拿去核实；有授权 Webhook 和核销记录接口。云飞可以作为备选，前提是它能提供 HTTPS 接口和授权文件。
2. **在 Go 后端定义一个「团购核销」平台适配接口**（比如 `Prepare / Consume / Cancel / Status` 四个动作，带幂等键）。聚合服务只是其中一个实现，以后能换成抖音直连，或者换成自己的服务商身份。**券码不要写死长度，金额字段不要当成结算金额。**
3. **抖音：同时申请「自研商家」直连**（来客绑定开发者，开通团购核销、对账能力）。批下来就绕开聚合，还能拿到分账明细；批不下来就继续走聚合。
4. **一定要保留人工兜底**：聚合服务或授权失效时，用美团经营宝和抖音来客 App 直接核销，再在自己系统里补录。
5. **对账**：每月用经营宝、来客后台的结算账单和自己系统里的核销记录对一遍。不要指望聚合 API 给结算金额。
6. **小红书**：暂不接入系统。如果要卖，就在小红书商家后台手工核销、系统里补录，每半年复查一次开放平台。
7. **预充值只充小额**（无限聚核的 500 元档就够单店用一年多），控制服务商跑路的损失。

**做 SaaS 时（以后）**

- 按美团规则，SaaS 通过聚合服务给其他门店核销，会让我们直接成为规则禁止的「其它软件厂商」。**做 SaaS 前必须自己成为官方服务商**：美团服务零售要 WAF 证明、等保或网络安全保险、10 万保证金；抖音要通过技术服务商认证。适配层设计好了，这时只需要换一个实现。

## 8. 需要向服务商确认的问题

**资质与合规**

1. 你们和美团、抖音签约的主体是谁？能不能提供美团合作授权书原件或合同主体页、抖音服务商认证截图？授权书编码能不能向美团核实？（无限聚核的授权书授权方是「天津汉博信息技术有限公司」）
2. 美团《运营管理规则》禁止把接口能力「通过接口转让、接口数据传输、售卖等方式提供给其它软件厂商应用」。你们这种 API 转售模式有没有得到美团书面认可？如果被美团处罚停用，对客户怎么补偿、怎么退余额？
3. 商家授权时，美团、抖音官方授权页上显示的应用或服务商名称是什么？（我们会实际走一遍验证）
4. （问云飞）营业执照主体是公司还是个体工商户？能不能开增值税专票？

**能力**

5. 是否支持**美发（丽人·服务零售）**门店？有没有已上线的美发客户？无限聚核文档列的场景是棋牌室、台球、健身、民宿、茶室。
6. 大众点评券是不是和美团券走同一个接口、同一次授权？（官方接口里 `platform` 字段 1=美团，2=点评）
7. 美团、抖音的团购次卡、阶梯次卡、代金券都能核销吗？能撤销吗？
8. 有没有结算金额（扣佣金后的到账金额）？能不能透传美团财务接口、抖音分账明细接口 `ledger.query_record_by_cert`？
9. 有没有核销、撤销、退款的 **Webhook** 推送？用户在平台侧退款时，我们能不能收到通知？
10. 能不能提供 **HTTPS** 接口？（问云飞）access_token 能不能不放在 URL 里？
11. 有没有测试环境、测试券？有没有 Go 示例？

**商务与运维**

12. 云飞的验券单价具体多少？各充值档位分别是多少？
13. 余额能不能退？服务终止时余额怎么处理？
14. SLA 具体条款：可用性、故障响应时间、赔付方式？出过几次平台侧断连，多久恢复的？
15. 数据处理：你们留存哪些字段（手机号、订单号、券码）？留多久？能不能签数据处理协议？
16. 授权有效期多长？过期前会不会提醒？换绑门店、解除授权怎么做？
17. 有没有小红书团购核销的计划和时间表？
