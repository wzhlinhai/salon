# 美管加完整功能清单（菜单 → 功能 → 操作）与本店近 12 个月使用情况

对应：[美管加与博卡完整功能清单](https://github.com/wzhlinhai/salon/issues/21) 的美管加部分（博卡部分另行调研）。用途：给「P0 功能范围取舍」提供完整依据，并为 [ADR-0002](../adr/0002-business-rules-are-per-store-settings.md)（业务规则做成每店设置）提供"现有产品暴露了哪些设置"的证据。

## 结论摘要

1. **美管加分三端**：电脑后台（6 个模块、133 个菜单，另有约 690 个不在菜单树里的接口，覆盖收银单据管理、营销、商城、企业微信、支付等）；**小掌柜**（员工/收银端，开单、收银、轮牌、考勤打卡、看业绩都在这里）；**美一客**（顾客小程序：预约、商城、会员卡）。电脑后台的接口目录里**没有"新建水单/结算"接口**，开单收银实际在小掌柜完成。
2. **本店真正在用的**（2025-10-15 至 2026-10-15）：项目消费水单 9,407 张、开卡 98、充值 486、套餐购买 33；美团/点评团购 2,495 客次、抖音团购 910 客次；扫码收款（当面付）1,959 笔且 1,953 笔已关联水单；**考勤打卡 1,010 人·天，覆盖 366 天里的 334 天**；轮牌（剪发牌、助理牌启用且与收银联动，最近一次轮转在 2026-10-15）；每月工资提成表 12/12 个月、10 名员工；会员卡自动升级 63 次；事后改单/补人约 1,100 次（系统操作日志）；员工权限/角色调整 76 次；后台登录 769 次、小掌柜登录 785 次。
3. **确认在美管加里没用的**：支出 / 其他收入记账（2020-06 起全部为 0）、预约（门店预约数 0、预约记录空）、库存（12 个产品，近 12 个月 0 次入库、1 次出库、1 次卖品销售）、工资审核与锁定、员工奖罚、请假/临休、审批、短信、营销活动、企业微信、退卡审批（最新读取 0 条）。
4. **功能全景漏掉的**（详见第 5 节）：考勤打卡与班次、工资表（月度工资汇总）、系统操作日志、员工档案管理（入职/离职/恢复）、角色与权限、支出记账、余额/卡资料的手工调整（带审计）、会员卡**自动升级规则**、红包、顾客来源、项目按条件改价与会员价、支付方式的业绩计入比例、收款流水与单据关联对账。
5. **阶段可能有误的**：考勤（后期 → 应为 P0/P1）、工资表（后期 → 应并入 P0 的提成结算单）、预约（P0 → 本店在美管加里一次没用，可降为 P1）、库存（待定 → 本店基本不用，可定为后期）、退卡（P0 → 近 12 个月 0 次审批，可评估降为 P1）。

## 1. 依据与口径

| 来源（nice-salon 仓库，只读） | 用来做什么 |
|---|---|
| `mgj-cli/接口总目录.md`（1,457 条接口，含中文用途、菜单映射、读写分类） | 功能和操作的全集；读/写判断以该目录的「类别」列为准（按前端证据判读，未在线验证副作用） |
| `mgj-cli/data/reference/aten-20261005/菜单树-本地库对照.txt`、`mgj-cli/mgj/catalog.json`（`mgj menus` 命令的数据） | 电脑后台菜单树：6 个模块、133 个菜单 |
| `mgj-cli/只读接口数据分类.md` | 权限树（`authSet!singleAuthSet` 149 项，本店门店账号已授 117 项）中已知的权限代码；各接口有数据/确认空/受阻的判定 |
| `mgj-cli/data/readable.sqlite`（只读打开） | 本店使用量。员工端菜单树来自 `role/get_info`，员工端权限项来自 `role/get_menus_permission`，设置字段来自各配置接口的最新读取 |

**时间窗口**：2025-10-15 至 2026-10-15。有业务日期的记录按日期精确计数（按单号/记录号去重）；只有按月窗口的数据（报表类、`coverage_windows`）按 2025-11 至 2026-10 共 12 个月计，下文标"按月"。

**三种使用状态**：

- **数字**：窗口内的记录数（单据张数、客次、人·天、日志条数等，单位随行注明）。
- **确认为空**：该功能的读取接口在窗口内成功读通且为 0 行（或配置/统计值为 0）。只说明本账号、本门店、本次参数下为空。
- **无法判断**：说明原因。最常见的三类：① 报表、看板是"查看"功能，美管加不留浏览记录，只能看到底层数据有没有；② 小掌柜端的过程性操作（挂单、轮牌轮转、打印）只留当前快照，没有历史流水；③ 接口受阻（模块未开通、缺对象参数、权限不足）。

**系统操作日志**（`sysLog!sysSensitiveLog`，窗口内 4,527 条）是判断"事后修改"类操作用了多少次的主要依据，下文引用时标"日志"。日志按操作类型分类计数，不含任何人名。

**未做的事**：没有联网、没有调用任何美管加接口；没有读 `.env`、`auth/`；文中不含顾客或员工的姓名、手机号、编号。

## 6. 局限

- 读/写分类来自前端代码判读，没有执行写操作验证副作用；10 条接口按"保守管理"计为写。
- 小掌柜（员工/收银端）只有员工角色的菜单和权限数据，没有小掌柜自身的接口目录；开单、挂单、轮牌轮转、打卡的操作次数只能从结果数据（水单、考勤记录、日志）推出。
- 权限树 149 项只有已知代码，没有完整清单。
- "确认为空"只代表本账号（门店账号，非总店账号）、本门店、读取时的参数；本店账号缺权限的功能（会员生日、门店参数设置、积分兑奖规则、门店库存全套、供应商）列为无法判断或按受阻处理。
- 系统操作日志从 2025-01-01 起有数据，窗口内完整；日志里同一操作可能写多条（例如"会员卡充值"969 条多于水单的 584 次开充卡），按条计数，不等于业务次数。
- 报表浏览频率、打印次数、导出次数，美管加都不留记录，一律无法判断。
