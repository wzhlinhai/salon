# 功能全景（草案）

把国内主流美发 SaaS（博卡、美管加、美团客满满、有赞美业、伊智）和开源美业系统的功能汇总成我们自己的功能清单。每一项写明借鉴自哪家、我们打算怎么做得更好、建议放在哪个阶段。

**这是草案，供店主取舍，阶段划分不是定论。** 依据：

- [国内主流美发 SaaS 功能调研](https://github.com/wzhlinhai/salon/blob/research/china-salon-saas-features/docs/research/2026-10-19-china-salon-saas-features.md)
- [开源美业系统功能调研](https://github.com/wzhlinhai/salon/blob/research/open-source-salon-systems/docs/research/2026-10-18-open-source-salon-systems.md)
- 店里美管加的使用数据（[店里固定事实问卷](https://github.com/wzhlinhai/salon/issues/2)）

**阶段**：

- **P0**：替换美管加必须有的，加上 ADR-0001 定的一个只读 AI 功能；
- **P1**：P0 上线后紧接着做；
- **后期**：做成产品、SaaS 阶段；
- **不做**：已在地图里排除，或者不值得做。

## 我们比现有产品好在哪（贯穿所有模块）

现有产品的共同痛点，和我们针对每个痛点的做法：

| 痛点 | 我们的做法 |
|---|---|
| 提成规则不够灵活，月底反复核对 | 规则做成每店可设置的参数（ADR-0002）；**每一笔提成都能追溯到哪张单、哪条规则、哪个版本**，员工和 AI 都能解释"这笔为什么是这么多"；改规则前可以**试算**"按新规则，上个月的提成会变成多少" |
| 后台复杂，员工学不会 | 每个角色只看到自己用得到的几个页面；**能直接对 AI 说话来操作**，例如"给王姐开个烫发，指定小李"，AI 先生成草稿，由人确认（ADR-0001） |
| 录错了只能删单重开（本店一年 110 次）、事后改提成员工（316 单）、事后补人（94 次） | 单据能直接修改，不用删掉重开；每次修改自动留下修改前后的对照和修改人，余额和提成自动按差额调整；开卡、充值时强制选业绩归属人，事后补人走一步确认 |
| 团购要手工选渠道（本店一年约 3,470 单） | 核销团购券时自动识别是哪个平台，**核销后直接生成单据** |
| 按端口、按功能分开收费，续费涨价 | SaaS 阶段的定价原则：小程序、员工端不单独收费（P0 不涉及） |
| 数据导不出，换系统难 | 任何时候都能全量导出（顾客、卡、余额流水、单据、提成）；P0 要能从美管加导入 |
| App 闪退、长期不更新 | 只做网页和小程序，不做原生 App |

1. 两个 **P0 候选** AI 功能（经营日报 + 预警、对话查数据）选哪个，或者两个都做。
2. 标为 P0 的条目里，有没有可以往后推的。P0 越小越早上线。
3. 标为 P1、后期的条目里，有没有你觉得必须放进 P0 的。
