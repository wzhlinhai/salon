# 每张单都关联顾客，认不出身份的也建档；顾客档案不清理

开单时如果顾客没有留手机号，系统自动建一个未识别顾客档案，不要求前台多填。这样散客的单也能进入经营分析，比如渠道、项目偏好、客数、新客有没有回头。顾客档案不按时间清理，也不按数量清理。本店一年新增顾客是几百到几千人，十年累计几万条，存储没有压力。删掉档案会让单据失去关联，也会让以前来过的人再来时被误当成新客。

以下规则已由店主于 2026-10-20 确认。

- **识别靠强线索，自动进行**：完整手机号、付款账号一致，就认定是同一人，自动关联，不需要员工操作。
- **弱线索只提示，不自动合并**：例如团购核销返回的打码手机号。这类疑似重复放进一个列表，店长有空时处理。没人处理也不影响数据正确，只是暂时认不出来。
- **不靠员工凭记忆认人**：发型师不一定记得住，忙的时候也想不起来。合并顾客只是店长在后台整理数据的工具。
- **只隐藏，不删除**：顾客列表和搜索默认不显示未识别顾客，需要时可以筛选出来。
- **报表里新客、老客要多一类“无法判断”**：未识别顾客不直接算新客。

## Considered Options

- **散客不建档，单据上只记“散客”**：未被采纳。无法分析散客的渠道和偏好，以后拿到手机号也补不回历史。
- **定期清理或超过一定数量就清理**：未被采纳。数据量很小，清理的好处抵不上历史数据的损失。
- **弱线索自动合并**：未被采纳。合错了会把两个人的单和卡混在一起，比认不出来麻烦得多。
- **由发型师认出熟客、当场确认**：未被采纳。这样要靠员工额外操作，违背“数据只来自店里本来就要做的事”的原则。

## Consequences

- 同一手机号只能有一个顾客，但没有手机号的顾客可以有很多个。
- 付款账号要等线上收款通道（#44）开通才有，团购打码手机号来自团购核销（#46）。这两种线索的存储由那两张票各自添加，顾客档案（#29）只用手机号识别，不预先建空的线索表。合并顾客时有测试检查所有引用顾客的表都被处理，以后加的线索表也逃不过。
- 识别率主要取决于有没有开通自己的收款通道，“无法判断”的比例要在报表里如实显示。
