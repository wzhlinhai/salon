# P0 的范围是成熟综合美发单店的基础能力

P0 要实现的是成熟综合美发单店的基础能力：店里开展的每一项业务，P0 都必须正确支持，不能用"先做一部分"代替。P0 之外的功能只有两类：店里不开展的业务，或者属于产品化、连锁和分析增值的能力。

判断一项功能是否属于 P0，按以下标准（任一满足即可）：

- 本店正在开展这项业务（美管加使用记录、或店主确认的日常流程）；
- 成熟单店缺了它，经营流程就无法正常运转（例如退卡、封账、挂账、手工费、多人分业绩）。

基础能力清单的依据有三份：开源美业系统调研（第一、三、四节，列出各项目的可配置做法）、美管加完整功能清单（本店 12 个月使用数据）、博卡功能清单。逐项的阶段标注在 `docs/feature-catalogue.md`。

**预约**属于 P0。店主 2026-10-19 确认：预约是成熟单店的基础能力，本店目前使用次数为 0，但能力要保留。P0 包括员工代约、顾客小程序预约、改约、取消、状态流转、防冲突，以及营业时段和可约天数等规则设置。爽约限制、超时提醒、到店前提醒放 P1。

## Considered Options

- **P0 只做本店在美管加里真的在用的功能**：未被采纳。会漏掉成熟单店缺了就跑不起来的能力，例如退卡（退套餐在用，退卡规则没做的话，退款就没有依据）、封账、手工费。
- **P0 做成熟 SaaS 的全部功能，包括连锁、库存、商城**：未被采纳。超出单店范围，会拖慢 P0 上线。

## Consequences

- 功能清单中的每个 P0 行都要有对应的业务规则设置（ADR-0002）和 AI 接口（ADR-0001），两者缺一不可。
- 有公开做法的基础能力，按调研的做法实现；没有公开做法的，做成可设置项并给默认值（ADR-0002）。
- P0 不能以"数据先存、界面后做"的方式跳过业务能力：`P0 数据` 只允许用于店里暂时不在用、但为了不改数据结构必须预留的字段。
- 新增或调整 P0 范围，要同时更新功能清单和本 ADR。
