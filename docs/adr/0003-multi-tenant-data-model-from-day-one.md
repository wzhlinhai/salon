# 数据从第一天按多租户设计，P0 只开一个租户

> 部分被 [ADR-0005](0005-franchise-store-is-own-tenant.md) 取代：加盟店与总部各自是一个租户，本文中"老板（租户管理者）看全部门店"的假设只适用于一个老板拥有多家门店的情况。

数据结构从第一天就按多租户来做：分**租户**（一个老板或一个品牌）和**门店**两层，一个租户下可以有多家门店。每条业务数据都带租户和门店，用 PostgreSQL 行级安全按租户隔离；业务设置（见 ADR-0002）挂在租户或门店上。P0 只开店主自己这一个租户、一家门店，租户开通、套餐计费、连锁总部报表等功能都不做，但以后加这些功能时不需要改数据结构。

## Considered Options

- **先按单店做，做 SaaS 时再加租户**：未被采纳。到时候每张表都要补租户字段、迁移历史数据、补权限检查，漏一处就会让一家店看到另一家店的数据。
- **只分门店一层，不分租户**：未被采纳。连锁店的一个老板有好几家店，要共用顾客、卡项和员工；只有门店一层的话，以后再加"租户"这一层同样要改数据结构。

## Consequences

- 每张业务表都有租户字段，每次查询都受行级安全约束，开发和测试时要始终带着租户上下文。
- 同一租户下的门店之间也要隔离：员工默认只能看到自己门店的数据，只有老板（租户管理者）能看全部门店。这一层由业务接口的权限检查负责，AI 调用同样受限。
- 顾客、卡、员工归属租户（见 [ADR-0005](0005-franchise-store-is-own-tenant.md)）。卡的可用范围由发行门店和可用门店决定，P0 只允许卡在发行门店使用。
