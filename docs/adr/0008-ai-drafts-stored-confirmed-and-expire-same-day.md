# AI 草稿落库保存，当天有效，确认人必须有该操作权限

[ADR-0004](0004-p0-ai-drafts-writes-human-confirms.md) 规定 AI 只能起草，由人确认。本 ADR 定下草稿怎么存、谁能确认、什么时候失效、留下什么记录。

以下规则已由店主于 2026-10-19 确认。标注"可设置"的项，店主可以在系统设置里修改。

- **存储**：草稿是数据库里的一条记录，带租户和门店（[ADR-0003](0003-multi-tenant-data-model-from-day-one.md)）。内容包括：发起人、目标操作（如开单、改单、调整单）、员工原始口述、AI 给出的参数、面向人的摘要、状态（待确认、已确认、已拒绝、已过期、已被修改后确认）、创建时间、确认时间和确认人。
- **发起**：发起人必须本人有执行该操作的权限。创建草稿时检查一次。
- **确认**：确认人必须有执行该操作的权限，确认时再检查一次，因为权限可能已经变了。发起人本人可以确认自己的草稿（员工口述后自己核对）。
  - 可设置：涉及金额的操作（调整单、撤单、退卡、改价）可以设为必须由另一人确认。默认不强制。
- **修改**：确认前，人可以修改草稿参数，修改前后的内容都保留。修改后确认的，状态记为"已修改后确认"。
- **过期**：草稿在所属营业日结束前有效。过期后不能确认，要重新起草。营业日在第二天的"营业日结束时间"截止，这是一项门店设置（[ADR-0002](0002-business-rules-are-per-store-settings.md)），与营业时段的关门时间分开设置，因为关门后可能还有收尾的单。可设置为其他时长。
- **执行**：确认后，操作走原来的业务接口，有完整的权限检查和业务规则。产生的业务记录要关联草稿 ID，能从业务记录反查到草稿，也能从草稿查到业务记录。
- **拒绝、过期、修改**都留痕，不删除草稿。

## Considered Options

- **草稿只存在前端会话里，不落库**：未被采纳。断线或刷新就丢失，无法审计，也无法回答"这笔单是 AI 起草的还是人录的"。
- **草稿长期有效，不过期**：未被采纳。旧草稿可能在状态已经变化后被误确认，例如顾客已经换了项目。
- **草稿必须双人确认**：未被采纳为默认值。6–15 人的店里，每笔开单都要双人确认会拖慢前台；只对金额类操作提供可设置的双人确认。

## Consequences

- 需要一张草稿表和对应的接口：创建、查询、修改、确认、拒绝。这些接口本身也是 AI 接口（[ADR-0001](0001-every-business-operation-is-ai-callable.md)）。
- 团购核销后开单（ADR-0004 第 3 项）的草稿，需要关联核销记录；核销本身由员工在前台触发，不由草稿确认触发。
- 测试要覆盖：权限变化后确认被拒、过期后确认被拒、修改后确认的留痕、业务记录能反查草稿。
