# 后台设计语言

后台的所有页面都按本文的布局、颜色、字体和组件规则来做。新页面照做；改旧页面时顺手对齐，规则冲突时以本文为准。

风格参照 Notion：底色安静，颜色只用在标签和状态上，信息靠留白和细线分组，不靠卡片和色块。使用场景是店里的平板和电脑，同一台设备可能由手湿的助理点按。

## 原则

1. **安静**：页面大部分是黑、灰、白。彩色只出现在三处：主操作按钮、状态标签、服务分类标签。
2. **只标异常**：正常状态（启用、在职、可预约）不加徽标，只给停用、离职、迟到、缺卡这类需要注意的状态加。
3. **AI 起草，人确认**（ADR-0004、ADR-0008）：AI 的产出以草稿形式出现，总是带 AI 标识，并且总有确认、修改、拒绝三个动作。
4. **手动兜底**：每个 AI 能做的操作，页面上都有普通入口。AI 入口不替代按钮和表单。
5. **能点中**：触屏上可点区域至少 44×44px，鼠标下至少 24×24px（WCAG 2.5.5 / 2.5.8）。

## 外壳

用 Nuxt UI 的 Dashboard 组件搭外壳，不自己写侧栏和顶栏：

```text
<UDashboardGroup>
  <UDashboardSidebar>              左侧栏，可折叠
    门店名（以后切换门店）
    <UDashboardSearchButton>       "搜索或吩咐 AI"，Ctrl K
    待确认（数字 = 待我确认的草稿数）
    分组导航
    底部：当前用户菜单（改密码、退出）
  <UDashboardPanel>                主区
    <UDashboardNavbar>             顶栏，只有一行
      左：面包屑（门店 / 页面 / 当前对象）
      右：本页的一个主操作 + ··· 菜单
    页面内容
  <UDashboardSearch>               全局搜索框，Ctrl K 或点侧栏按钮弹出
```

侧栏导航分组（`utils/nav.ts` 加 `group` 字段，没有权限的项照旧隐藏，整组都没有权限时连组名一起隐藏）：

| 分组 | 页面 |
|---|---|
| （无组名） | 首页、收银、预约、顾客 |
| 员工 | 员工、考勤、工资表、提成规则、级别与岗位 |
| 项目与卡 | 项目与价格、卡类型、团购商品、团购对账 |
| 设置 | 角色与权限、门店设置 |

侧栏里只有一个 AI 入口，就是"搜索或吩咐 AI"，不另设"问 AI"。在首页，这个框直接展开在页面里；在其他页面，它以弹层出现。需要来回追问的对话在右侧滑出的面板里进行，不做单独的 AI 页面，也不做浮动聊天气泡。

## 颜色

在 `app.config.ts` 里设置，页面里只用语义名（`primary`、`neutral`、`error` 等），不直接写 `text-green-500` 这类色值。

| 语义 | Tailwind 色板 | 用在哪 |
|---|---|---|
| `neutral` | `stone` | 文字、边框、底色。stone 偏暖，接近 Notion 的灰 |
| `primary` | `blue` | 主操作按钮、选中项、焦点框 |
| `ai` | `violet` | 只用于 AI：AI 标识、指令框图标、AI 提示条。要在 `nuxt.config.ts` 的 `ui.theme.colors` 里注册 |
| `success` | `green` | 成功提示；表格里尽量不用 |
| `warning` | `amber` | 迟到、早退、待处理 |
| `error` | `red` | 缺卡、安全标签、删除、失败 |
| `info` | `sky` | 少用 |

底色层次：页面白色，侧栏 `bg-muted`（stone-50），悬停 `bg-elevated`。卡片不加底色，用 1px `border-default` 的细线分开。

**服务分类标签**：项目类别是门店设置，名字由店里自己定，所以颜色不按"剪、染、烫"写死，而是按类别的排序依次取下面的浅色标签（`UBadge variant="subtle"`），超出 8 个就循环：

`blue`、`orange`、`pink`、`green`、`amber`、`sky`、`rose`、`stone`

不用 `violet`，它留给 AI。排班格、看板卡片、订单行上的分类标签都用同一套颜色。

## 字体和数字

- 字体：系统无衬线字体加 Noto Sans SC（`ui-sans-serif, -apple-system, "Segoe UI", "Noto Sans SC", "Microsoft YaHei", sans-serif`）。不用衬线字体。
- 所有金额、时间、数量都用等宽数字：`tabular-nums`。
- 字号只用下面几级：

| 用途 | 写法 |
|---|---|
| 首页问候 | `text-2xl font-bold` |
| 页面标题（顶栏面包屑里的当前页） | `text-sm font-medium`，顶栏下不再重复写一个大标题 |
| 页面内大标题（详情面板里的对象名） | `text-xl font-semibold` |
| 区块标题 | `text-sm font-medium text-muted`，前面可带一个图标 |
| 正文、表格 | `text-sm` |
| 辅助说明、表头 | `text-xs text-muted` 或 `text-sm text-muted` |
| 指标数字 | `text-2xl font-semibold tabular-nums` |

- 标题加 `text-wrap: balance`（Tailwind `text-balance`），说明文字加 `text-pretty`。

## 圆角、边框、阴影、间距

- 圆角：`--ui-radius: 0.375rem`（6px，按钮、输入框、标签）；卡片和看板列用 `rounded-xl`（12px）。
- 边框：一律 1px `border-default`。不用粗边框和彩色边框；状态用标签表达，不用边框颜色。
- 阴影：只给浮层（弹窗、下拉、侧滑面板、看板卡片）。页面里的卡片不加阴影。
- 间距以 4px 为基数。主区内边距 `p-6`；区块之间 `gap-6`；区块标题和内容之间 `gap-2`；表格行高至少 40px，触屏至少 44px。
- 主区内容最大宽度：列表和工作台页面铺满；首页和设置页居中，最大 `max-w-5xl`。

## 页面骨架

每个页面从上到下最多四层，按需省略：

1. **顶栏**（`UDashboardNavbar`）：面包屑，加右侧一个 `primary` 实心按钮（如"新建顾客"），其他操作收进 ··· 菜单。
2. **一句说明**（可选）：`text-sm text-muted`，只在规则容易误解时写，比如"修改从选定日期开始执行"。
3. **工具条**（`UDashboardToolbar`）：左边是视图切换（如有）和搜索框，右边是筛选。筛选控件不加上方标签，用占位文字说明。
4. **内容**：从下面五种内容模式里选一种。

一个页面只有一个实心主按钮。其他按钮用 `variant="outline"` 或 `"ghost"`，颜色用 `neutral`。

## 内容模式

| 模式 | 用在 | 怎么做 |
|---|---|---|
| **表格** | 顾客、员工、项目与价格、卡类型、团购商品、提成方案版本、角色 | `UTable`。名称列是普通深色文字，不做彩色链接；整行可点，点开右侧详情。多个属性分成多列，不在一个格子里堆"种类 服务 / 标准价 100 元"这样的多行文字。正常状态不显示徽标 |
| **属性行** | 门店设置、详情面板里的字段 | 左边是名称（`text-muted`，固定宽度），中间是当前值，右边是"修改"（`ghost` 按钮）。一组设置放进一个带细线的容器，每项一行，不要每项一张卡片。说明文字放在名称下面一行 |
| **时间轴** | 预约、首页排班 | 每行一位员工，横轴是时间；预约块用分类颜色；当前时间用一条 `error` 色竖线；服务中、待收银、迟到用块的边框和标签区分 |
| **工作台** | 收银 | 左边是列表（挂单），右边是当前对象的详情和操作。用两个 `UDashboardPanel`，中间可以拖动调宽 |
| **指标卡** | 首页、团购对账、工资表汇总 | 一行 3 到 5 个，卡片只放名称、数字和一行对比，不放图标 |

### 详情：侧滑还是弹窗

- **查看或编辑一个已有对象**（顾客、员工、项目、预约）：用右侧滑出的面板（`USlideover side="right"`，对应 Notion 的 side peek），不离开列表。
- **新建、短表单（6 个字段以内）**：`UModal`。
- **确认危险操作**（删除、退卡、撤单）：`UModal`，确认按钮用 `color="error"`。
- 保存成功用 `useToast()` 提示，不弹窗。

## 组件约定

- **按钮**：默认尺寸 `md`；表格行内的操作用 `size="sm" variant="ghost"`。不用文字链接做操作。
- **徽标**：一律 `variant="subtle"`。状态和颜色固定对应：

| 状态 | 颜色 |
|---|---|
| 停用、离职、已取消、已过期 | `neutral` |
| 迟到、早退、待确认、待收银 | `warning` |
| 缺卡、安全标签、失败 | `error` |
| 服务中、执行中 | `primary` |
| AI 起草、AI 发现 | `ai` |

- **图标**：只用 Lucide（`i-lucide-*`），不用 emoji。导航每项一个图标；按钮只有在没有文字时才单用图标，此时必须有 `aria-label`。
- **日期和金额**：日期写 `11 月 20 日 周五`，表格里写 `2026-11-20`；时间写 `14:08`；金额写 `¥1,268.00`，指标卡里整数金额可以省掉小数。
- **空状态**：一句话说明，加上能解决它的那个按钮（如"还没有项目" + "新建项目"）。
- **触屏**：在 `main.css` 里用 `@media (pointer: coarse)` 把按钮、输入框、导航项的最小高度提到 44px，不另做平板版页面。
- **次要操作**放进 `UDropdownMenu`（··· 菜单）。不要在顶栏并排摆三个以上的按钮。

## AI 的位置

AI 只出现在下面四个位置，每处都用 `ai` 颜色和 `i-lucide-sparkles` 图标标出来：

1. **指令框**：同一个框既能搜索，也能吩咐 AI。说一句话，AI 生成草稿；输入名字，就是搜索。助理首页把它放大摆在正中，下面放推荐说法和一排快捷按钮；店长首页只占一行，放在收件箱下面；其他页面按 Ctrl K 或点侧栏弹出。
2. **草稿收件箱**（"待确认"）：每张草稿卡片上写清楚发起人和时间、员工原话、AI 理解的结果（改了什么，从多少改成多少），再加确认、修改、拒绝三个按钮。确认用 `neutral` 实心按钮，不用 `primary`，避免和页面主操作抢视线。
3. **嵌在业务数据旁的一句话**：指标下面的一句解释，排班格下面的冲突提醒加"起草改约"按钮，顾客卡片上的档案摘要。AI 只提醒和起草，不自动修改数据。
4. **侧栏入口**："搜索或吩咐 AI"加"待确认"计数。

不做：浮动聊天气泡、单独的 AI 页面、AI 主动弹出的窗口。AI 发现的问题一律进收件箱。

## 首页

首页按角色显示不同内容，版式相同：居中问候，下面依次是：

- **店长**：待你确认（草稿卡片）→ 一行指令框 → 今日经营指标卡（下面加一句 AI 解释）→ 今日排班时间轴（下面是 AI 提醒）。
- **助理**：大指令框加推荐说法 → 快捷按钮（散客开单、新预约、办卡充值、打卡）→ 我起草的 → 今日顾客看板（稍后到店、服务中、待收银）。

## 验收

动到界面的工单，交付时附上改动页面的截图：电脑 1366×900 一张，平板 1024×768 一张。截图要用虚构数据。验收时对照截图逐条检查本文的规则，至少包括：颜色只用语义名、一个页面只有一个实心主按钮、正常状态不加徽标、不用 emoji、平板上的按钮够大。
