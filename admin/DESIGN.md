# 后台设计系统

后台的每个页面都按本文来做：新页面照做，改旧页面时顺手对齐。写界面的 AI 和人在动手前读完本文，交付前按"验收"一节逐条自查。

## 依据，按优先级

1. **J/K 原型**：`.dev/design/dashboard-directions/j.html`（店长首页、前台首页）和 `k.html`（个人首页），以及同目录的 `notion.css`。这是视觉的最终标准，和本文其他部分冲突时以原型为准，然后回来改本文。
2. **参考图**：`.dev/design-refs/picked/`，每张图用在哪页、拿什么，见同目录的 `README.md`。原型没画到的页面（日历、结账、详情面板、报表、登录等）照参考图的结构来做，再套上本文的颜色和字体。原始图库在 `.dev/design-refs/raw/`（Mobbin、Dribbble、21st、Bencho，约 220 张）。这些图只在本机，不入库，不发给外部服务。
3. **网页基本功**：Google 的 modern-web-guidance（github.com/GoogleChrome/modern-web-guidance）。本文"网页基本功"一节摘录了和后台相关的条目。

不用设计类 skill 生成风格，也不照搬 Nuxt UI 的默认外观。21st、Bencho 是 React 组件库，只看交互和结构，不搬代码。

## 风格

像 Notion：暖白底、暖灰字、细线分组，颜色只用在标签和状态上。信息靠留白和细线分组，不靠色块。使用场景是店里的平板和电脑，同一台设备可能由手湿的助理点按。

1. **安静**：页面大部分是黑、灰、白。彩色只出现在主操作按钮、状态标签、服务分类标签和 AI 上。
2. **只标异常**：正常状态（启用、在职、可预约）不加标签，只给停用、离职、迟到、缺卡这类要注意的状态加。
3. **AI 起草，人确认**（ADR-0004、ADR-0008）：AI 的产出以草稿出现，带 AI 标识，并且总有确认、修改、拒绝三个动作。
4. **手动兜底**：AI 能做的每个操作，页面上都有普通入口。
5. **一屏看完**：首页和工作台页在 1366×900 下不滚动就能看到最重要的那一块。

## 设计令牌

全部定义在 `app/assets/css/main.css` 的 `@theme` 和 `:root` 里。**组件里只写令牌名，不写色值、阴影和任意尺寸**（不写 `bg-[#f4f4f2]`、`shadow-[…]`、`text-[13px]`）。需要新值时先加进 `main.css` 并在本表登记，再用。

| `bg-ai-soft`、`text-ai` | #f3effb、#7b55c7 | 只给 AI：AI 标识、指令框、AI 提示条 |

### 标签色

Notion 的九种浅底标签，类名 `bg-tag-*`，配合 `tag` 工具类（20px 高、3px 圆角、12px 字）：

`gray` `brown` `orange` `yellow` `green` `blue` `purple` `pink` `red`

- **服务分类**：项目类别是门店设置，名字由店里定，所以颜色按类别的排序依次取 `blue orange pink green purple yellow brown`，超出就循环，没有类别用 `gray`。统一用 `useItemTones()` 取，时间轴、看板卡、订单行、项目表都用它，不在页面里另排一套。
- **状态**：

| 状态 | 标签 |
|---|---|
| 停用、离职、已取消、已过期、计数 | `bg-tag-gray` |
| 待确认、待收银、早退 | `bg-tag-yellow` |
| 迟到、缺卡、爽约、失败、安全标签 | `bg-tag-red` |
| 服务中、已到店、我 | `bg-tag-blue` |
| 已完成、已结清 | `bg-tag-green` |
| AI 起草、AI 发现 | `bg-ai-soft text-ai` |

### 字号

| 类名 | 大小 | 用途 |
|---|---|---|
| `text-greet font-bold` | 26px | 首页问候、登录页标题 |
| `text-hero font-bold` | 40px | 单个超大数字（轮牌"第 3 位"） |
| `text-2xl font-semibold` | 24px | 指标卡数字 |
| `text-xl font-semibold` | 20px | 详情面板里的对象名 |
| `text-lead` | 15px | 卡片里的人名、大输入框 |
| `text-sm`（正文默认 14px） | 14px | 正文、表格、按钮 |
| `text-meta` | 13px | 区块标题、说明、卡片附注 |
| `text-xs` | 12px | 标签、表头、时间轴块 |
| `text-2xs` | 11px | 时间轴块第二行、角标 |

- 字体：`ui-sans-serif, -apple-system, "Segoe UI", "Noto Sans SC", "Microsoft YaHei", sans-serif`，不用衬线体。
- 金额、时间、数量一律 `tabular-nums`。
- 标题加 `text-balance`，段落说明加 `text-pretty`。

### 圆角、投影、间距

| 类名 | 值 | 用在 |
|---|---|---|
| `rounded-tag` | 3px | 标签、时间轴的当前时间牌 |
| `rounded-md`（`--ui-radius`） | 6px | 按钮、输入框、导航项 |
| `rounded-lane` | 10px | 看板列、一行的小指令框 |
| `rounded-card` / `box` | 12px | 卡片 |
| `rounded-panel` | 14px | 前台首页的大指令框 |
| `shadow-line` | 1px 细线 | 输入框、时间轴块 |
| `shadow-card` / `box` | 细线 + 1px 影 | 卡片、看板卡 |
| `shadow-float` | 细线 + 14px 影 | 浮起的输入框；弹层用 Nuxt UI 自带 |
| `shadow-raised` | 1px 影 | 分段切换里选中的那一段 |

- 卡片统一用 `box` 工具类（白底、12px 圆角、`shadow-card`、14px×16px 内边距），不另写一套。
- 间距以 4px 为基数。主区内边距 `p-6`；区块标题 `sec` 自带上 22px、下 8px；卡片之间 `gap-3`；表格行至少 40px，触屏 44px。
- 内容宽度：首页居中，最大 1060px（个人首页 1000px）；表格和工作台页铺满；设置页居中，最大 `max-w-3xl`。

### 其他工具类

- `sec`：区块标题。左边图标加名字，右边 `ms-auto font-normal text-dimmed` 写一句说明或一个链接。
- `hatch`：斜纹底，表示"被占着但还没有顾客"（私约占位、歇业时段）。
- `ring-serving` / `ring-alert`：时间轴块的状态描边，深色是服务中，红色是迟到、爽约。块里同时写出状态文字。

## 图标

- **页面图标和区块标题用 emoji**，照原型和 Notion：侧栏每项一个（`utils/nav.ts` 的 `emoji`），区块标题前一个（📅 今日排班、📊 今日经营）。待确认和我起草的用 `◉`，AI 用 `✦`。一律 `aria-hidden="true"`，旁边必须有文字。
- **按钮和操作用 Lucide**（`i-lucide-*`）。只有图标的按钮必须有 `aria-label`。
- 同一个概念全站用同一个图标，新增时先查 `nav.ts` 和本节。

## 外壳

用 Nuxt UI 的 Dashboard 组件搭（`app.vue`），样式照原型 J 的侧栏：

```text
<UDashboardGroup>
  <UDashboardSidebar>  bg-side，可折叠
    门店名（首字做标志）
    ✦ 搜索或吩咐 AI     Ctrl K
    ◉ 待确认            数字 = 待我确认的草稿数
    分组导航            emoji + 名称；没权限的项隐藏，整组都没有就连组名隐藏
    个人菜单            打卡、我的考勤、改密码、退出
  <UDashboardPanel>    bg-page
    顶栏                一行：左边页面 emoji + 名称；右边本页一个主操作 + ··· 菜单
    页面内容
```

| 分组 | 页面 | 谁用 |
|---|---|---|
| 门店 | 首页、轮牌、收银、预约、顾客 | 日常，人人都用 |
| 经营 | 日结、售后、报表、团购对账 | 店长 |
| 员工 | 员工、考勤、工资表、提成规则、级别与岗位 | 店长 |
| 项目与卡 | 项目与价格、卡类型、团购商品 | 店长、老板 |
| 设置 | 门店设置、角色与权限、数据导入 | 老板 |

页面的进入条件按"能在这页做的最基本的事"定，页面里超出权限的部分整块隐藏，不显示空壳。例如收银页：有开单权限（`order.create`）就能进；结账、核销团购券、撤单只有对应权限的人看得到。

## 页面骨架

从上到下最多四层，按需省略：

1. **顶栏**：页面名称，右边一个实心主按钮（如"新建顾客"，用 `PageActions` 放进顶栏，`size="sm"`），其他操作收进 ··· 菜单。顶栏下不再重复写大标题。
2. **一句说明**（可选）：`text-meta text-muted`，只在规则容易误解时写。
3. **工具条**：左边视图切换和搜索框，右边筛选。筛选控件不加上方标签，用占位文字说明；日期范围用弹出月历，不跳页（参考 table-02）。
4. **内容**：从下面的内容模式里选。

一个页面只有一个实心主按钮。其他按钮用 `variant="outline"` 或 `"ghost"`、`color="neutral"`。

每种模式先看对应的原型或参考图（文件在 `.dev/design-refs/picked/`），再动手。

### 详情、弹窗和提示

- **查看或编辑一个已有对象**（顾客、员工、项目、预约）：右侧滑出面板（`USlideover side="right"`），不离开列表。面板顶部是对象名、主操作和分节，下面是余额、指标小卡、近期记录（参考 drawer-01）。
- **新建、短表单（6 个字段以内）**：`UModal`，字段可两列，底部"取消"描边、"保存"实心（参考 modal-01）。
- **确认危险操作**（删除、退卡、撤单）：`UModal`，确认按钮 `color="error"`，按钮文字写出动作（"撤单"，不写"确定"）。
- **保存成功**：`useToast()`，不弹窗。
- **行内操作**：表格每行的次要按钮（档案、角色、停用…）平时隐藏，鼠标移到行上或键盘聚焦时出现，触屏始终显示。金额列的 0 用淡色，让有数的格子跳出来。
- **空状态**：用 `EmptyState`，一句话说明 + 能解决它的那个按钮（"还没有项目" + "新建项目"）；这个按钮已经在顶栏时不再重复，提示里指向右上角。筛选无结果：一句话 + "清除筛选"（参考 empty-01、empty-03）。列表里某列为空写"没有"，不画插图。

## 组件约定

- **按钮**：默认 `md`；表格行内的操作 `size="sm" variant="ghost"`。不用文字链接做操作。次要操作放进 `UDropdownMenu`（···），顶栏不并排三个以上按钮。
- **标签**：状态和分类用 `tag` + `bg-tag-*`（见"标签色"），不用 Nuxt UI 默认的 `UBadge` 配色。
- **日期和金额**：日期 `11月20日 周五`，表格里 `2026-11-20`；时间 `14:08`；金额 `¥1,268.00`：列表、明细和弹窗用 `utils/money.ts` 的 `yuanFixed()`，指标卡用 `yuan()`（整数金额省掉小数），不在组件里另写格式化。例外：工资表和工资明细整页都是钱，用不带 `¥` 的两位小数；储值卡流水的「前 + 变动 = 后」算式也保持纯数字。指标卡没有可比数据时，小字写这个数的口径（如"不含办卡充值"），不写"无数据"。时区一律 `Asia/Shanghai`。
- **人名**：顾客没留名写"未留名顾客"；轮牌、我的顾客里本人写"我"。
- **头像**：没有照片就用名字首字放在圆里（`HomeRotation` 的写法）。

## AI 的位置

AI 只出现在下面四处，都用 `text-ai` 和 `✦`：

1. **指令框**（`AiCommandBox`）：同一个框既能搜索也能吩咐 AI。前台首页用 `large`，大框在正中，推荐说法排在框下；店长首页和个人首页是一行的小框，推荐说法排在框里；其他页面按 Ctrl K 或点侧栏。来回追问在右侧滑出的对话面板里进行。
2. **待确认**（草稿收件箱，`DraftCard`）：每张草稿写清发起人和时间、员工原话、AI 理解的结果（改了什么、从多少改成多少），再加确认、修改、拒绝。确认用实心深色按钮，不用 `primary`，不和页面主操作抢。
3. **业务数据旁的一句话**：指标下的解释、排班冲突提醒加"起草改约"、顾客卡片上的档案摘要。AI 只提醒和起草，不自动改数据。
4. **侧栏入口**："搜索或吩咐 AI"和"待确认"计数。

不做：浮动聊天气泡、单独的 AI 页面、AI 主动弹出的窗口。AI 发现的问题一律进待确认。

## 首页

按这个人的**权限并集**决定首页，不按角色名字（角色可以改名、新建，一人可多角色，ADR-0009）：

| 首页 | 条件 | 典型的人 |
|---|---|---|
| 店长首页 | 有 `report.view` | 老板、店长 |
| 前台首页 | 有 `payment.collect` 或 `queue.operate` | 兼接待收银的助理 |
| 个人首页 | 以上都没有 | 发型师、洗头助理 |

- 从上往下取第一个符合的。同时符合多个的人，顶栏右侧有一个分段切换，只列他符合的几种，记住上次的选择；别人看不到这个切换。
- 首页里每一块按权限显示，没权限整块不显示。

三种首页都是居中问候加日期，下面是：

- **店长首页**（原型 J 左）：◉ 待你确认 → 一行指令框 → 📊 今日经营指标卡 + AI 一句话 → 📅 今日排班时间轴 + AI 提醒。
- **前台首页**（原型 J 的助理视图）：大指令框 + 推荐说法 → 快捷按钮（散客开单、新预约、办卡充值、打卡）→ ◉ 我起草的 → ▥ 今日顾客看板。
- **个人首页**（原型 K）：没打卡时最上面是 `bg-notice` 打卡提醒 → 一行指令框 → 🔁 轮牌（我排第几）→ 👥 我的顾客 → 📅 我的今天（只有我一行的时间轴）→ 我今天的业绩和提成 → ◉ 我起草的。

**时间轴按实际服务来画**：本店主要靠轮牌派客，很少预约（见 `docs/feature-catalogue.md`）。所以时间轴同时画预约、私约占位和正在服务的散客（挂单），不能只画预约。

## 网页基本功

摘自 modern-web-guidance，写界面时逐条做到：

- **点得中**：可点区域鼠标下至少 24×24px，触屏（`pointer: coarse`）至少 44×44px，`main.css` 已统一提高按钮、输入框、导航项的最小高度。自己画的可点元素也要满足。
- **不只靠颜色**：状态一定有文字或图标（"迟到 12 分"，不只是红框）。文字对比度至少 4.5:1，边框和状态标记至少 3:1；`text-dimmed` 只用于次要说明，不用于唯一的信息。
- **语义和读屏**：按钮用 `<button>`，跳转用链接；只有图标的按钮写 `aria-label`；装饰性 emoji 和图标 `aria-hidden="true"`；表单控件都有可见标签或 `aria-label`。
- **文字不定高**：文字容器不写固定 `height`，要撑开时用 `min-h-*`；标题不截断，确实要截断的（人名、时间轴块）用 `truncate` 并在 `title` 里给全文。
- **能缩**：1024px 平板下不横向滚动；窄到 320px 内容能重排，不给 `body` 加 `overflow-x: hidden` 掩盖溢出。卡片组和看板用网格在窄屏折成一列；组件自身的布局随容器变时用容器查询（`@container`）。
- **内容优先**：不弹没人要的窗口。阻断式弹窗只给有后果的操作，其他用 toast 或页内提示。常驻的条（顶栏、提醒条）只占一行。次要内容放进 ··· 菜单、弹出层或侧滑面板，不要堆在页面上。
- **颜色混合**：需要某个令牌的浅一档时用 `color-mix(in oklab, var(--color-…) N%, #fff)`，不另写新色值。
- **深色模式和强制颜色**：现在只做浅色。状态不能只靠 `box-shadow` 画出（强制颜色模式下会消失），所以状态文字是必需的。

## 验收

动到界面的改动，交付前：

1. **并排对照**：用虚构数据截图（1366×900 一张，1024×768 一张，时区 Asia/Shanghai），和原型或参考图拼成左右并排的一张图逐处比。原型画到的页面对原型，没画到的对 `picked/README.md` 里列的那张参考图。差异要么改掉，要么写明原因。
2. **规则自查**：
   - 组件里没有任意色值、阴影和字号（`grep -rnE "(bg|text|shadow|rounded)-\[" app` 只剩尺寸类）。
   - 一个页面只有一个实心主按钮。
   - 正常状态不加标签；状态都有文字。
   - emoji 只在侧栏和区块标题里，且 `aria-hidden`；只有图标的按钮有 `aria-label`。
   - 平板上可点区域够 44px；1024px 下不横向滚动。
3. **lint、typecheck、相关 e2e** 都过。
