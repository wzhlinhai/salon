# 后台设计系统

后台的每个页面都按本文来做：新页面照做，改旧页面时顺手对齐。写界面的 AI 和人在动手前读完本文，交付前按"验收"一节逐条自查。

## 依据，按优先级

1. **Notion 实测值**：2026-11-22 用户定下「完全仿 Notion」。内容区的颜色、字号、表格、页签、投影照下面「Notion 实测值」一节，那是从 Notion 公开页面读出的计算样式和像素，不是凭印象。和本文其他部分冲突时以实测值为准，然后回来改本文。侧栏保持现状。
2. **J/K 原型**：`.dev/design/dashboard-directions/j.html`（店长首页、前台首页）和 `k.html`（个人首页），以及同目录的 `notion.css`。首页的结构以原型为准，颜色和字号让位给 Notion 实测值。
3. **参考图**：`.dev/design-refs/picked/`，每张图用在哪页、拿什么，见同目录的 `README.md`。原型没画到的页面（日历、结账、详情面板、报表、登录等）照参考图的结构来做，再套上本文的颜色和字体。原始图库在 `.dev/design-refs/raw/`（Mobbin、Dribbble、21st、Bencho，约 220 张）。这些图只在本机，不入库，不发给外部服务。
4. **网页基本功**：Google 的 modern-web-guidance（github.com/GoogleChrome/modern-web-guidance）。本文"网页基本功"一节摘录了和后台相关的条目。

不用设计类 skill 生成风格，也不照搬 Nuxt UI 的默认外观。21st、Bencho 是 React 组件库，只看交互和结构，不搬代码。

## 风格

像 Notion：白底、暖灰字、细线分组，颜色只用在标签和状态上。信息靠留白和细线分组，不靠色块。使用场景是店里的平板和电脑，同一台设备可能由手湿的助理点按。

1. **安静**：页面大部分是黑、灰、白。彩色只出现在主操作按钮、状态标签、服务分类标签和 AI 上。
2. **只标异常**：正常状态（启用、在职、可预约）不加标签，只给停用、离职、迟到、缺卡这类要注意的状态加。
3. **AI 起草，人确认**（ADR-0004、ADR-0008）：AI 的产出以草稿出现，带 AI 标识，并且总有确认、修改、拒绝三个动作。
4. **手动兜底**：AI 能做的每个操作，页面上都有普通入口。
5. **一屏看完**：首页和工作台页在 1366×900 下不滚动就能看到最重要的那一块。

## 设计令牌

全部定义在 `app/assets/css/main.css` 的 `@theme` 和 `:root` 里。**组件里只写令牌名，不写色值、阴影和任意尺寸**（不写 `bg-[#f4f4f2]`、`shadow-[…]`、`text-[13px]`）。需要新值时先加进 `main.css` 并在本表登记，再用。

### 标签色

Notion 的九种浅底标签，类名 `bg-tag-*`，配合 `tag` 工具类（20px 高、3px 圆角、12px 字）：

`gray` `brown` `orange` `yellow` `green` `blue` `purple` `pink` `red`

- **服务分类**：项目类别是门店设置，名字由店里定，所以颜色按类别的排序依次取 `blue orange pink green purple yellow brown`，超出就循环，没有类别用 `gray`。统一用 `useItemTones()` 取，时间轴、看板卡、订单行、项目表都用它，不在页面里另排一套。
- **状态**：

| 状态 | 标签 |
|---|---|
| 停用、离职、已取消、已过期、计数 | `bg-tag-gray` |
| 待确认、待收银、早退 | `bg-tag-yellow` |
| 迟到、缺卡、爽约、失败、安全标签 | `bg-tag-red` |
| 服务中、已到店、我 | `bg-tag-blue` |
| 已完成、已结清 | `bg-tag-green` |
| AI 起草、AI 发现 | `bg-ai-soft text-ai` |

### 字号

| 类名 | 大小 | 用途 |
|---|---|---|
| `text-title font-bold` | 32px | 页面标题（`app.vue` 统一生成）、首页问候 |
| `text-greet font-bold` | 26px | 登录页标题 |
| `text-hero font-bold` | 40px | 单个超大数字（轮牌"第 3 位"） |
| `text-2xl font-semibold` | 24px | 指标卡数字 |
| `text-xl font-semibold` | 20px | 详情面板里的对象名 |
| `text-lead` | 15px | 卡片里的人名、大输入框 |
| `text-sm`（正文默认 14px） | 14px | 正文、表格、按钮 |
| `text-meta` | 13px | 区块标题、说明、卡片附注 |
| `text-xs` | 12px | 时间轴块 |
| `text-2xs` | 11px | 时间轴块第二行、角标 |

- 字体：照 Notion，只用系统字体，不打包网页字体。正文 `ui-sans-serif, -apple-system, BlinkMacSystemFont, "Segoe UI Variable Text", "Segoe UI", "PingFang SC", "Noto Sans SC", "Microsoft YaHei UI"…`；`text-title`、`text-hero`、`text-greet` 换成 `Segoe UI Variable Display`（Windows 11 的光学尺寸：Text 给小字，Display 给大标题）。中文先取微软雅黑 UI 版（行高为界面收紧过）。不用衬线体。
- 金额、时间、数量一律 `tabular-nums`。
- 标题加 `text-balance`，段落说明加 `text-pretty`。

### 圆角、投影、间距

| 类名 | 值 | 用在 |
|---|---|---|
| `rounded-tag` | 4px | 标签、时间轴的当前时间牌 |
| `rounded-md`（`--ui-radius`） | 6px | 按钮、输入框、导航项 |
| `rounded-lane` | 10px | 看板列 |
| `rounded-card` / `box` | 12px | 卡片 |
| `rounded-panel` | 14px | 前台首页的大指令框 |
| `shadow-line` | 1px 细线 | 输入框、时间轴块 |
| `shadow-card` / `box` | 细线 + 1px 影 | 卡片、看板卡 |
| `shadow-float` | 细线 + 14px 影 | 浮起的输入框；弹层用 Nuxt UI 自带 |
| `shadow-raised` | 1px 影 | 分段切换里选中的那一段 |

- 卡片统一用 `box` 工具类（白底、12px 圆角、`shadow-card`、14px×16px 内边距），不另写一套。
- 间距以 4px 为基数。主区内边距上 40px、左右 48px，`xl` 起 96px（窄屏 16px）；区块标题 `sec` 自带上 28px、下 8px；卡片之间 `gap-3`；表格行至少 40px，触屏 44px。
- 内容宽度：首页居中，最大 960px（照 Notion 首页）；其他页面见"页面骨架"的两档宽度。

### 其他工具类

- `ViewTabs`（组件）：列表上方的视图页签，照 Notion 数据库的视图切换。灰底胶囊是当前视图，其余灰字，名称后跟灰色数量；按钮带 `aria-pressed` 和 `data-filter`。日结、员工、顾客分组、团购对账的平台都用它。
- `props`：照 Notion 页面属性的两列清单（`<dl class="props">`，`dt` 灰字属性名、`dd` 值）。几个数字讲同一件事、不值得画表时用（团购对账）。
- `tile`：大筛选块，现在只剩轮牌的队列切换在用；新页面用 `ViewTabs`（白底细线、10px 圆角，`aria-pressed="true"` 时描 1.5px 蓝色 outline，强制配色模式下也看得见）。里面上一行 `text-meta` 名称，下一行 `text-xl font-semibold` 数量；选中时两行都 `text-primary`，数量是 0 或是「已停用」这类不常看的用 `text-dimmed`。
- `sec`：区块标题，16px 半粗墨色。只写名字，不加图标；右边 `ms-auto font-normal text-dimmed` 写一句说明或一个链接，`font-normal` 的子元素自动用 14px。
- `stats`：指标条。不包卡片，上下各一条细线，数字直接放在页面上。
- `hatch`：斜纹底，表示"被占着但还没有顾客"（私约占位、歇业时段）。
- `ring-serving` / `ring-alert`：时间轴块的状态描边，深色是服务中，红色是迟到、爽约。块里同时写出状态文字。

## 去掉 AI 套路

2026-11-22 对照 Anthropic 的 frontend-design 技能（它列出的五类 AI 设计套路）、Chrome 的 Modern Web Guidance 和几篇独立博客（mowgli.ai「15 个痕迹」等）查过一遍。下面这些是 AI 生成界面最常见的痕迹，本系统不用：

- **紫色和闪光符号当 AI 标志**（紫色渐变、✦、sparkles）。AI 用自己的形象 `AiMark`，AI 产出的东西用文字「AI 起草」标明。
- **每个标题前一个装饰图标**。图标只用来找东西和表示动作（见「图标」）。例外：首页组件卡的卡内标题照 Notion 首页带一个灰色小图标。
- **一样的圆角白卡片一张叠一张**。卡片只给能单独操作的东西（草稿、看板卡、轮牌卡、时间轴网格）；指标用 `stats` 细线条，表格不包卡（见「表格」）。
- **随机彩色首字头像**。头像一律灰底。
- **复述标题的说明句**、到处都有的小字标签。说明只写口径和规则。
- **为了显得完整而多加的导航**：内容一屏就能看完还配分类栏或目录（6 张报表配「全部 / 营业 / 员工…」）、既把全部内容铺开又另放跳转目录、分页或区块标题和页面标题同名（「卡类型」页里再写「卡类型 0」、「待确认」页的第一个分页也叫「待确认」）、二级页没有回上一级的路。导航只在内容多到找不着时才加，加了就只显示选中的那部分。
- **大数字卡片当筛选按钮**：用 `ViewTabs` 视图页签，数量跟在名称后面；数字背后的补充（本月到店多少位）写在「共 N 位」后面。
- **一个强调色以外再加一个**。彩色只给主按钮（蓝）、状态和分类标签；确认草稿、AI 发送用深色。

新页面交付前，拿截图对一遍这个清单。

## 图标

- **全站只用 Lucide 线条图标**（`i-lucide-*`），单色、不用 emoji。**图标只放在帮人找东西的地方**：侧栏每项一个（`utils/nav.ts` 的 `icon`，18px，墨色线条，右下角垫一块错开的圆色块，颜色是该项的 `tone`（标签色，加深一档），和空状态插画同一种画法；侧栏收成图标条时只剩它）、顶栏面包屑一个（16px）、按钮和输入框里表示动作的一个。页面标题、区块标题、指标卡前面不放图标，名字已经说清楚了。待确认和我起草的用 `DRAFTS_ICON`（inbox）。
- **AI 不用 `✦` 和 sparkles**：指令框前面是搜索图标（它本来就是搜索框）。AI 的形象是 `AiMark`：一笔画的小脸，头顶一缕卷发刘海，两团淡粉腮红（原创，不照搬 Notion 的角色）；用在右下角按钮、AI 面板标题前，以及面板还没对话时底部的招呼（大号形象 +「店里的事，跟我说。」，照 Notion 的 AI 面板）。AI 的东西用「AI 起草」文字标签标明。
- 装饰性图标一律 `aria-hidden="true"`，旁边必须有文字。
- 只有图标的按钮必须有 `aria-label`。
- 同一个概念全站用同一个图标，新增时先查 `nav.ts` 和本节。

## 页面骨架

从上到下最多五层，按需省略（照 Notion 的整页数据库）：

1. **顶栏**：左边是小字面包屑（页面图标 + 名称，`text-muted`），右边一个实心主按钮（如"新建顾客"，用 `PageActions` 放进顶栏，`size="sm"`），其他操作收进 ··· 菜单。
2. **页面标题**：正文最上面，`text-title font-bold`（32px）名称，不加图标。由 `app.vue` 按导航自动生成，页面里不再自己写标题；首页没有标题，用问候代替；工作台类页面（收银、预约，`definePageMeta({ workbench: true })`）也不放大标题，顶栏面包屑已经写了页名，标题只留给读屏。
3. **一句说明**：标题下一行 `text-muted`，只写标题说不清的事（口径、规则、生效方式，例如营业报表的「实收不含办卡充值」），写在 `definePageMeta({ description })` 里；把标题换个说法再说一遍的（「顾客档案、卡和到店记录」）不写，没有就省掉这一行；工作台类页面（收银、预约）省掉，把高度留给内容。随数据变的半句（"今天是营业日 2026-11-22。"）用 `<PageDescriptionTail>` 接在末尾，不另起一行灰字。
4. **视图和工具条**：要切换看哪一类的，用 `ViewTabs`（名称 + 灰色数量，例如员工页「在职 5 · 未开通账号 1 · 已停用 0」），天数、总数这种没信息量的不写数。搜索框和视图页签在同一行（照 Dribbble 上的列表页：左边视图，右边搜索 + 「共 N 人」），搜索框用 `variant="ghost"` 不描边，占位文字写能搜什么；还有别的筛选（负责人、排序）放第二行，也用 ghost 下拉。改条件就直接刷新，不放「查询」按钮。筛选控件不加上方标签；日期范围用弹出月历，不跳页（参考 table-02）。
5. **内容**：从下面的内容模式里选。

- **宽度只有两档**：默认铺满主区（表格、日历、工作台、列表）；设置类页面在 `definePageMeta` 里写 `width: 'narrow'`，居中、最宽 800px。首页自己管宽度（见"首页"）。页面里不再另写 `max-w-*` 和 `mx-auto`。
- **页面根节点**一律 `space-y-4`，块与块之间不另调间距。

一个页面只有一个实心主按钮。其他按钮用 `variant="outline"` 或 `"ghost"`、`color="neutral"`。

### 详情、弹窗和提示

- **查看或编辑一个已有对象**（顾客、员工、项目、预约）：右侧滑出面板（`USlideover side="right"`），不离开列表。面板顶部是对象名、主操作和分节，下面是余额、指标小卡、近期记录（参考 drawer-01）。顾客详情（`CustomerDetail`）照此分两栏、各自滚动：左栏只放这个人本身——首字头像、名字、手机号，主操作「修改资料」加 ··· 菜单（补/改手机号、安全标签、合并），一组带灰色图标的资料行（空的写「性别未填」这类淡字）；右栏顶上一排分页（概览、卡、红包、欠款、修改记录，没权限的不出现），**一次只显示一页**，当前分页写在网址里（`?id=…&tab=cards`），换顾客回到概览。概览是卡余额、累计消费、来过、上次到店四个指标（`stats` 细线条），下次预约和上次做了什么，安全标签。分页里不再写和分页同名的标题，只留数量和操作（「2 张」「开卡」）。不要既把全部内容铺开、又另放一个跳转目录。指标取自顾客列表那一行（`utils/customer.ts` 和列表共用说法）。卡行只露「充值」，其余收进行尾 ···（改卡一组、看记录一组、退卡单独一组）。
- **新建、短表单（6 个字段以内）**：`UModal`，全站弹窗和侧滑面板一套样式，照 Fresha 的弹窗（参考 modal-01，`picked/modal-01-fresha-time-off.png`）。样式写在 `app.config.ts` 的 `modal`、`slideover`、`formField` 和 `main.css` 的 `.dialog-form`、`.dialog-actions`，页面上不另写：
  - **骨架**：标题栏、内容区、按钮栏三段，中间各一道细线。标题 18px 半粗；标题下的一句说明写在 `description` 里（"从 2026年11月 起执行"、"在营业日结束时间前补卡，会算到前一个营业日。"、当前对象"王老板 · 2026-11-23 09:00"），**不在内容区开头或末尾另写说明段落**。默认宽 480，字段多的写 `:ui="{ content: 'sm:max-w-[600px]' }"`。
  - **字段**：标签在控件上方，14px 半粗墨色；控件铺满一栏，44 高、8 圆角、白底一圈灰框（#d6d3d1），聚焦时框变墨色；说明（`help`，不用 `hint`）和报错在控件下方 13px 灰字。只属于某一个字段的说明写成那个字段的 `help`（"当前：未设置"挂在「员工」下）。字段之间 `space-y-5`。
  - **两列**：成对的短字段并排（`grid grid-cols-2 gap-4`）：手机号和姓名、性别和来源、开始和结束时间、日期和时间、本金和赠送金、面额和售价、原卡类型和目标卡类型。长文本、多选、项目清单占整行。一组多行的值（级别价、开单的项目）用 `FieldGroup`，最后一个「＋ 添加」文字按钮。
  - **金额汇总**（退卡、结账明细）：一行一项，左名目灰字、右金额，最后一行合计 15px 半粗、上方一道线。
  - **去向选择**（新增预约选代约还是私约占位）：不用一排小按钮，做成整行选项：左图标、名称加一句说明、右箭头，一圈灰框。
  - **按钮栏**：右对齐，按钮 44 高、8 圆角、15px 字；"取消"白底灰框墨色字，"保存"实心蓝（主色仍是 Notion 蓝）。一律用 `ModalActions` 组件，不在弹窗里自己摆按钮；危险操作的主按钮换 `color="error"`，左边可以放一句状态或次要操作（"已选 3 个"、"恢复系统默认"）。
- **确认危险操作**（删除、退卡、撤单）：`UModal`，确认按钮 `color="error"`，按钮文字写出动作（"撤单"，不写"确定"）。
- **保存成功**：`useToast()`，不弹窗。
- **行内操作**：表格每行的次要操作收进行尾 ··· 菜单（`aria-label` 写"某某 的操作"），按钮平时隐藏，鼠标移到行上或键盘聚焦时出现，触屏始终显示；操作只有一两个的表格可以直接放 ghost 按钮，同样悬停才出现。例外是操作台式的列表（轮牌）：每行当前状态下最常用的那一个操作（点客、撤销接客、取消盖牌、到岗）常显，其余照样收进 ···。金额列的 0 用淡色，让有数的格子跳出来；报表明细的表身里 0 写成一道淡色短横（`yuanCell`，客数单数同样），合计行照写数。报表明细行加 `row-hover`（悬停整行浅暖灰，左侧固定列跟着变），合计行 `bg-side`。
- **空状态**：日历、时间轴这类空了也要留着网格的页面，在网格上浮一句提示，说清从哪儿开始（预约页"点空白时段，或右上角「新建预约」"）。其他列表用 `EmptyState`，一句话说明 + 能解决它的那个按钮（"还没有项目" + "新建项目"）；这个按钮已经在顶栏时不再重复，提示里指向右上角。筛选无结果：一句话 + "清除筛选"（参考 empty-01、empty-03）。页面级的「还没有数据」（还没有项目、本月还没有工资、这段时间没有业绩）在 `EmptyState` 上加 `art`，放一张店里物件的小线稿（`SpotArt`：剪刀、理发椅、小票、柱状图、会员卡、日历；墨色细线加一块低饱和标签色圆，照 Notion 页内插画）。出错、筛选无结果、卡片里的小空状态不放插画；行式列表里主值为空写"没有"，表格里空格留白。
- **加载**：列表第一次加载用 `ListSkeleton`（几行灰条，放进 `UTable` 的 `#loading` 插槽或自己画的列表里），不写"加载中…"；已有数据时刷新保留旧行。

## 组件约定

- **按钮**：默认 `md`；表格行内的操作 `size="sm" variant="ghost"`。不用文字链接做操作。次要操作放进 `UDropdownMenu`（···），顶栏不并排三个以上按钮。禁用的实心按钮是灰底灰字（`app.config.ts` 统一设好），旁边要有一句话说明为什么现在不能点。
- **日期和月份输入**：一律用 `DateInput`（加 `month` 就是选月份），框里显示 `2026-11-22`，能直接键入，右边按钮弹出中文月历；`min`、`max` 照常传。不用浏览器原生 `type="date"` / `type="month"`，它按系统语言显示成 `11/22/2026`。
- **标签**：状态和分类用 `tag` + `bg-tag-*`（见"标签色"），不用 Nuxt UI 默认的 `UBadge` 配色。
- **日期和金额**：日期 `11月20日 周五`，表格里 `2026-11-20`；时间 `14:08`；金额 `¥1,268.00`：列表、明细和弹窗用 `utils/money.ts` 的 `yuanFixed()`，指标卡用 `yuan()`（整数金额省掉小数），不在组件里另写格式化。例外：工资表和工资明细整页都是钱，用不带 `¥` 的两位小数；储值卡流水的「前 + 变动 = 后」算式也保持纯数字。指标卡没有可比数据时，小字写这个数的口径（如"不含办卡充值"），不写"无数据"；数字是 0 时用 `text-dimmed`（`zeroText()`），一排黑色的 ¥0 像出了错。时区一律 `Asia/Shanghai`。
- **人名**：顾客没留名写"未留名顾客"；轮牌、我的顾客里本人写"我"。
- **头像**：没有照片就用名字首字放在灰底圆里（`bg-tag-gray`），不按人随机上色，名字本身就能区分人。

## AI 的位置

AI 只出现在下面四处，都用文字标明是 AI，不用专门的颜色和符号：

1. **右下角 AI 按钮**（照 Notion 右下角的 AI 按钮）：每一页都有，点开右侧对话面板，面板打开时收起；内容区底部留 64px，滚到底时最后一行不被压住（工作台页除外）。这是吩咐 AI 的主入口，来回追问都在右侧面板里进行。
   **指令框**（`AiCommandBox`）只留在前台首页：大框在正中，推荐说法排在框下，助理一天主要就是说一句话办一件事。店长首页和个人首页是用来看的，不放指令框（Notion 首页也没有）。Ctrl K 打开搜索，说一整句话时最后一项是「吩咐 AI：…」。
2. **待确认**（草稿收件箱，`DraftCard`）：每张草稿写清发起人和时间、员工原话、AI 理解的结果（改了什么、从多少改成多少），再加确认、修改、拒绝。确认用实心深色按钮，不用 `primary`，不和页面主操作抢。
3. **业务数据旁的一句话**：指标下的解释、排班冲突提醒加"起草改约"、顾客卡片上的档案摘要。AI 只提醒和起草，不自动改数据。
4. **侧栏入口**："搜索"（找顾客、找页面）和"待确认"计数；叫 AI 去右下角。

不做：浮动聊天气泡、单独的 AI 页面、AI 主动弹出的窗口。AI 发现的问题一律进待确认。

## 首页

按这个人的**权限并集**决定首页，不按角色名字（角色可以改名、新建，一人可多角色，ADR-0009）：

| 首页 | 条件 | 典型的人 |
|---|---|---|
| 店长首页 | 有 `report.view` | 老板、店长 |
| 前台首页 | 有 `payment.collect` 或 `queue.operate` | 兼接待收银的助理 |
| 个人首页 | 以上都没有 | 发型师、洗头助理 |

- 从上往下取第一个符合的。同时符合多个的人，顶栏右侧有一个分段切换，只列他符合的几种，记住上次的选择；别人看不到这个切换。
- 首页里每一块按权限显示，没权限整块不显示。

三种首页照 Notion 首页（参考图 `.dev/design-refs/notion-home.png`）：问候加日期居中，下面每一块是一张 `HomeWidget` 组件卡，块与块间距 16px：


- **店长首页**：最近访问（一排 150px 小卡片：灰色封面条、压在封面边上的 28px 图标、15px 页名、底下一行什么时候打开过；本人在这台电脑上最近打开的 6 个侧栏页面，不够用常用页面补，标「常用」）→ 待你确认（整行宽，一行一条草稿；没有时只占一行）→ 今日经营（一行一项：深色项目名、灰色比较、右对齐数字）和常用（有权限的前 4 个常用操作）左右并排 → 今日排班时间轴。
- **店长首页的组件卡里一律是清单行**（照 Notion 首页；个人首页的「我今天」等卡后续再对齐）：一行 36px，左边灰色小图标或深色 15px 名称，右边灰色补充；不在卡里放大数字块。卡里没东西时只写一行灰字，不撑出空白。
- **前台首页**（原型 J 的助理视图）：大指令框 + 推荐说法 → 快捷按钮（散客开单、新预约、找顾客、打卡；办卡充值要先选顾客，从找顾客进）→ 我起草的 → 今日顾客看板。
- **个人首页**（原型 K）：没打卡时最上面是 `bg-notice` 打卡提醒 → 轮牌（我排第几）→ 我的顾客 → 我的今天（只有我一行的时间轴）→ 我今天的业绩和提成（点提成从右侧滑出每笔怎么算）→ 我起草的。
- 问候按本地时间：0–5 点"夜深了"，5–12 点"早上好"，12–18 点"下午好"，之后"晚上好"。

**时间轴按实际服务来画**：本店主要靠轮牌派客，很少预约（见 `docs/feature-catalogue.md`）。所以时间轴同时画预约、私约占位和正在服务的散客（挂单），不能只画预约。

## 网页基本功

摘自 modern-web-guidance，写界面时逐条做到：

- **点得中**：可点区域鼠标下至少 24×24px，触屏（`pointer: coarse`）至少 44×44px，`main.css` 已统一提高按钮、输入框、导航项的最小高度。自己画的可点元素也要满足。
- **不只靠颜色**：状态一定有文字或图标（"迟到 12 分"，不只是红框）。文字对比度至少 4.5:1，边框和状态标记至少 3:1；`text-dimmed` 只用于次要说明，不用于唯一的信息。
- **语义和读屏**：按钮用 `<button>`，跳转用链接；只有图标的按钮写 `aria-label`；装饰性图标 `aria-hidden="true"`；表单控件都有可见标签或 `aria-label`。
- **文字不定高**：文字容器不写固定 `height`，要撑开时用 `min-h-*`；标题不截断，确实要截断的（人名、时间轴块）用 `truncate` 并在 `title` 里给全文。
- **能缩**：1024px 平板下不横向滚动；窄到 320px 内容能重排，不给 `body` 加 `overflow-x: hidden` 掩盖溢出。卡片组和看板用网格在窄屏折成一列；组件自身的布局随容器变时用容器查询（`@container`）。
- **内容优先**：不弹没人要的窗口。阻断式弹窗只给有后果的操作，其他用 toast 或页内提示。常驻的条（顶栏、提醒条）只占一行。次要内容放进 ··· 菜单、弹出层或侧滑面板，不要堆在页面上。
- **颜色混合**：需要某个令牌的浅一档时用 `color-mix(in oklab, var(--color-…) N%, #fff)`，不另写新色值。
- **深色模式和强制颜色**：现在只做浅色。状态不能只靠 `box-shadow` 画出（强制颜色模式下会消失），所以状态文字是必需的。

## 验收

动到界面的改动，交付前：

1. **并排对照**：用虚构数据截图（1366×900 一张，1024×768 一张，时区 Asia/Shanghai），和原型或参考图拼成左右并排的一张图逐处比。原型画到的页面对原型，没画到的对 `picked/README.md` 里列的那张参考图。差异要么改掉，要么写明原因。
2. **规则自查**：
   - 组件里没有任意色值、阴影和字号（`grep -rnE "(bg|text|shadow|rounded)-\[" app` 只剩尺寸类）。
   - 一个页面只有一个实心主按钮。
   - 正常状态不加标签；状态都有文字。
   - 没有 emoji 和 `✦`，图标都是灰色 Lucide 线条图标、只出现在侧栏、面包屑和动作上，且 `aria-hidden`；只有图标的按钮有 `aria-label`。
   - 对过「去掉 AI 套路」清单。
   - 平板上可点区域够 44px；1024px 下不横向滚动。
3. **lint、typecheck、相关 e2e** 都过。
